# 영수증 엔진 보강, 1.0.1 (32)

## 원인과 결정

빌드 31은 안전한 후보 표시까지는 개선했지만 정량 표본의 자동 선택이 1개에 그쳤다. 한국어를 우선하는 OCR 설정이 영어 약어를 훼손했고, 상품명과 가격 열을 화면 좌표의 높이만으로 연결해 기울어진 영수증에서 수량 근거가 분리됐다. 한국어 OCR의 0.5 신뢰도와 브랜드 상품명은 모두 수동 확인으로 남았다.

Apple의 [문서 인식 API 소개](https://developer.apple.com/videos/play/wwdc2025/272/)와 [문서 요청 API](https://developer.apple.com/documentation/vision/recognizedocumentsrequest)를 검토했다. macOS 26.6.2에서 같은 공개 사진 18장에 `RecognizeDocumentsRequest`를 실행했다. 5장에서 표를 반환했지만, 상품명만 있는 셀과 여러 숫자가 합쳐진 셀, 비어 있는 수량 열도 있었다. 이 결과만으로 구매 수량을 확정하는 경로는 채택하지 않았다. 앱은 iOS 18 이상에서 기존 Vision OCR을 사용한다.

[Foundation Models 가이드](https://developer.apple.com/documentation/FoundationModels/generating-content-and-performing-tasks-with-foundation-models)는 추출·분류를 지원하지만 기기와 모델 가용성에 제약이 있고 산술 검증을 대신하지 않는다. 이번 변경은 생성 모델에 구매량을 추측시키지 않고, 인식한 행과 가격 계산으로 확인하는 방식이다. 이미지와 텍스트는 기기 밖으로 보내지 않는다.

## 구현과 사용 흐름

- OCR 언어를 자동 감지한다. 식재료 사전 단어를 OCR에 강제로 주입하던 설정은 제거했다.
- 글자 사각형의 방향으로 읽기 좌표를 바로잡는다. 90도 누운 사진과 약간 기울어진 행의 상품명·가격을 같은 방향으로 읽는다. 원본 사진을 수정하거나 업로드하지 않는다.
- 한국어 단가·수량·금액 표에서는 단가 × 수량 = 금액을 검증한다. 포장 용량에 구매 개수를 곱하며, 포장 수만 확인되면 `1팩`으로 표시한다. 개별 두부나 바나나 개수로 바꾸지 않는다.
- `SEA`처럼 잘못 읽힌 개수는 제한된 문자 후보와 가격 계산이 모두 맞을 때만 복원한다. 계산이 맞지 않는 수량행과 누락된 수량 열은 확인 대상으로 남긴다.
- 정확한 전체 상품명 패턴과 명시적인 포장 단위를 확장했다. 한국어에서 낮은 OCR 신뢰도를 완화하려면 두 언어 설정의 결과가 같은 상품명·수량을 반환하고 가격 계산도 맞아야 한다. 두 OCR 결과가 독립적인 확률이라는 주장은 하지 않는다.
- 영어의 알 수 없는 앞말에 식재료 이름만 붙은 결과를 제외한다. 통조림 앤초비와 마른 멸치, 칠면조 베이컨과 일반 베이컨, 음료의 질량 온스와 액량 온스를 구분한다.
- 두 영수증의 바코드 열을 감지해 혼합 거래를 제외한다. 반품·비식품·세금·카드 정보 차단과 중복 행 확인도 유지한다.
- 화면은 바로 추가할 재료와 확인할 재료를 나눈다. 모르는 수량을 누르면 입력 칸에 바로 포커스한다. 빠진 재료를 수동으로 보충해도 기존 목록을 유지하고 마지막 버튼으로 함께 저장한다.

## 검증 범위

공개 사진은 총 20장, 한국 10장과 미국 10장이다. 원본은 로컬 평가용으로만 보관하며 출처·체크섬·정답은 [manifest.json](receipt-corpus/manifest.json)에 기록했다. 새 사진도 회전과 단위 처리 개선에 사용했으므로 독립 홀드아웃 성능으로 주장하지 않는다.

빌드 31과 비교하는 집합은 같은 13장, 사전에 대응시킬 수 있는 재료 종류 58개다. 다른 7장은 반품, 복수 영수증, 작은 배경 사진, 접힘·회전 등의 스트레스 사례다. 전체 식품 상품행을 모두 세는 재현율이 아니다.

| 같은 13장 비교 | 빌드 31 | 빌드 32 |
|---|---:|---:|
| 맞게 찾은 재료 종류 | 30/58 (51.7%) | 40/58 (69.0%) |
| 표시 후보의 재료 ID 정밀도 | 30/30 | 42/42 |
| 자동 선택 | 1개 | 13개 |
| 자동 선택 이름·수량·단위 대조 | 1개 수작업 확인 | 13/13 자동 검증 통과 |

20장 전체에서 자동 선택된 14개는 모두 사람이 확인한 이름·수량·단위와 일치했다. 추가 사진의 90도 회전 영수증에서 시금치 6oz를 올바르게 읽었다. 새 한국 영수증은 양상추와 달걀을 찾았지만 누락된 수량 열은 확인 대상으로 남겼다. 기존 두 영수증 혼합 사진 `kr09`는 후보 0개로 차단됐다. 작은 배경 사진 `us02`에는 주황 파프리카가 오렌지로 표시되는 수동 검토 후보가 남아 있다. 자동 선택은 되지 않으며, 이 사례를 완전히 해결했다고 주장하지 않는다.

단위 테스트 667개(648 Swift Testing + 19 XCTest), 한국어 첫 입력과 영수증 수량 확인·누락 재료 보충 UI 2개, 최종 실사진 20장 실행이 통과했다. 번역 검사 537키 / 351리터럴 / 누락 0건, diff 공백 검사도 통과했다. iOS 26.4 시뮬레이터 결과이며 실제 iPhone 카메라 속도·초점·빛 반사 검증은 별도다. 자동 선택은 사용자가 마지막 추가 버튼을 누르기 전의 선택 상태를 뜻한다.

자동 선택의 정답에는 이름뿐 아니라 수량과 단위도 포함한다. 사람이 원본에서 확인한 `verifiedQuantities` 목록과 비교하며, 같은 정답을 여러 번 소비할 수 없도록 테스트한다. 품목 수가 적은 편의 표본이므로 실제 사용자 사진 전체의 무오류를 보장하지 않는다. 읽히지 않은 상품과 불명확한 양은 추가하지 않고 확인을 요청한다.

## 간단 리뷰

새 서버, 외부 OCR 의존성, 개인정보 전송 없이 기존 엔진과 사전에 변경을 집중했다. 확인 버튼을 건너뛰는 저장 경로는 추가하지 않았다. 동일 상품 반복 행, 표의 구매 수량 누락, 서로 다른 OCR 결과, 식품 의미 변경을 검토하고 회귀 테스트로 고정했다. 특히 단위가 없다는 이유로 `1개`를 자동 확정하거나, 자동 선택률을 높이려고 OCR 신뢰도 기준만 낮추지 않았다.
