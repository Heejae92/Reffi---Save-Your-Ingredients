# 재료 입력 UX 개선

## 확인한 원인

- 홈의 주 버튼이 `View fridge`, 요리 추천은 보조 버튼으로 바뀌어 있었다. 냉장고 내비게이션과 목적지가 중복됐다.
- 영수증 파서는 사전 미매칭 텍스트도 상품명처럼 보이면 최대 12개까지 후보로 보존했다. 선택이 기본으로 꺼져 있어도 영수증 안내문과 생활용품이 화면에 섞일 수 있었다.
- OCR은 상품명과 용량을 다른 박스로 인식할 수 있는데, 기존 구현은 박스 위치를 버렸다. 인식 오류도 무시해서 실제 실패와 식재료 없는 결과가 구분되지 않았다.
- 영어 잡음 필터는 부분 문자열로 검사했다. `cashew`도 `cash` 때문에 제외되는 구조였다.
- 수동 입력은 이름 자동 매칭에 실패하면 기본 그림으로 저장했다. 추천 재료나 카테고리 선택, 그림 확인이 없었다.

## 반영한 흐름

1. 홈: 사용 가능한 재료가 있으면 파란 `Start cooking` 버튼으로 요리 추천을 연다. 없으면 재료 추가를 연다. 냉장고는 내비게이션에서 접근한다.
2. 영수증: 동일 행의 OCR 박스를 좌우 순서로 합치고, 재료 사전을 OCR 보조 단어로 제공한다. 식재료 사전 매칭 후보만 남기며, 생활용품·결제·상호 표현은 먼저 제외한다. 원문 영수증 행과 구매처 추정값은 결과에 노출하거나 자동 저장하지 않는다. 인식 실패와 일부 페이지 실패는 별도로 알린다.
3. 수동 입력: 입력에 맞는 재료를 최대 3개 추천하고, 선택한 재료 그림과 카테고리를 저장 전에 보여준다. 직접 카테고리를 바꿀 수 있다. 인식하지 못한 이름은 카테고리를 골라야 저장할 수 있다. 카테고리 선택은 재실행 후에도 유지한다.
4. 날짜: 카테고리만으로 특정 식재료의 소비기한을 추정하지 않는다. 기존의 추정 날짜 표시와 사용자 확인 흐름을 유지한다.

추가 실사진 분석과 자동 선택 정책은 [영수증 신뢰도 개선 리뷰](RECEIPT_RELIABILITY_REVIEW.md)에 기록했다.

## 남는 한계

- 제공된 사진은 홈 화면이며 실패한 영수증 원본은 없다. 오늘 사용한 실물 영수증의 정확한 OCR 실패 원인은 재현하지 못했다.
- 식재료 사전에 없는 식품은 자동 결과에서 빠질 수 있다. 비식품 정보를 보이지 않게 하려는 보수적인 정책이며, 빈 결과에서 수동 입력으로 바로 이동할 수 있다.
- 영수증 텍스트와 사전 기반 분류는 모든 상품을 완벽히 판별하지는 못한다. 새로운 브랜드 축약어와 흐린 사진은 실제 영수증으로 추가 검증할 필요가 있다.
- 기존에 저장된 잘못된 항목은 자동 삭제하지 않는다.

- OCR 검증: 생성한 영수증 이미지에서 우유·토마토만 추출하고 레몬 비누·합계·결제 정보 제외. 실제 실패 영수증에 대한 검증과는 구분한다.
