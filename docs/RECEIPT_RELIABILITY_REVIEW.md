# 빌드 31 영수증 입력 신뢰도 개선, 2026-09-20

이 문서는 빌드 31의 기록이다. 최신 결과는 [빌드 32 엔진 리뷰](RECEIPT_ENGINE_BUILD32.md)를 참고한다.

자동 선택은 재료 정체성, 수량 근거, OCR 품질이 모두 기준을 통과한 항목에만 허용한다. 사용자가 마지막 추가 버튼을 누르는 단계는 유지한다. 모든 영수증을 확인 없이 저장할 수 있다는 의미는 아니다.

## 변경과 간단 리뷰

- 홈의 주 버튼을 보유 재료로 요리를 찾는 `Start cooking`으로 복원했다. 냉장고 이동은 내비게이션에서 제공한다.
- 수동 입력에 재료 추천, 카테고리 선택, 그림 미리보기를 추가했다. 선택한 카테고리는 저장과 재실행 후에도 유지한다.
- 영수증은 앱과 평가 도구가 같은 `ReceiptRecognition` 경로를 사용한다. 외부 서버로 이미지나 OCR 텍스트를 보내지 않는다.
- 일반 검색용 퍼지 매칭을 영수증 확정에 사용하지 않는다. 두유·주스·가향유와 원재료를 구분하고, 미지원 복합상품을 원재료로 바꾸지 않는다. 영수증 전용 표기는 JSON으로 분리했다.
- 상품명만 인식하고 수량을 못 읽은 경우 `1개`를 확정하지 않는다. 목록은 `?`를 표시하고, 편집 화면에서 빈 수량을 입력해야 선택·저장이 가능하다. 저장 함수도 미확인 선택을 차단한다.
- 소수점 공백, 묶음 용량, 미국 단위를 처리한다. 별도 개수행은 단가×개수와 상품 금액이 일치할 때만 연결한다. 중복 행, 불명확한 묶음 기호, 수량 불일치는 확인 대상으로 남긴다.
- 반품 거래, 반복된 두 열 상품명, 합계·세금 이후 텍스트를 처리해 반품 재고 및 메모의 오인식을 막는다. 여러 영수증을 완벽히 감지하는 기능은 아니며, 감지한 경우 한 장씩 재촬영하도록 안내한다.
- 자동 선택과 검토 후보를 구분한다. OCR 신뢰도는 통계적으로 보정된 확률이 아니므로 이름 일치와 수량 근거를 함께 확인한다. 직접 입력한 수정값은 사용자의 명시적 확인으로 취급한다.

검토에서 추가로 수정한 문제: 낮은 신뢰도의 수량행이 높은 신뢰도의 상품명 뒤에 붙는 경우, 중복 상품행의 수량을 한 개로 확정하는 경우, 과일의 `40 CT` 등급 표기를 구매 개수로 해석하는 경우. 사진에서 발견한 오류를 회귀 테스트에 추가했다.

## 실제 사진 검증

기존 미국 8장·한국 8장에 새 출처의 미국 1장·한국 1장을 추가해 총 18장을 실행했다. 새 사진도 추가 오류를 발견하고 수정하는 데 사용했으므로 최종 결과를 독립적인 홀드아웃 성능이라고 부르지 않는다.

결과 수치는 아래 최종 실행 집계를 따른다. 정량 대상은 기존과 동일한 13장, 정답 재료 종류 58개다. 미지원 상품과 판독 불가능한 영역은 분모에서 제외되며 전체 식품 상품행·수량 정확도가 아니다.

최종 자동 선택은 **1건**(금액으로 수량을 검산한 바나나 7개)이며 원본과 일치했다. 나머지 29개 후보는 확인이 필요하다. 자동 선택 1건으로 일반적인 자동 입력 정확도를 입증할 수 없으며, 자동화 범위는 아직 좁다. 이 결과는 신뢰할 수 있는 항목만 자동 선택하도록 바꾼 근거이지 무검토 자동 입력의 출시 승인 근거가 아니다.
